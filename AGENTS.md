## Public text

This repo is public, and so is everything posted to it: issues, specs, PR descriptions, comments and commit messages. GitHub keeps edit history, so a later edit does not erase anything. Write all of it on a **need-to-know** basis, in a neutral, factual tone:

- Describe the desired result by its own features.
- Keep personal details to what the published site already shows. This applies to the owner and to third parties such as co-authors and advisors.
- Record decisions as settled facts, without the conversation behind them (question numbers, rounds, approvals given in chat).
- Raise sensitive findings with the owner in chat instead. These include flaws or inconsistencies in the owner's past work or content, possible rights problems, and details of the owner's machine, accounts or settings.

Before posting, reread the text the way a stranger would, such as a recruiter or a colleague. It is done when every sentence helps someone build or review the change and nothing in it would embarrass the owner. When unsure, ask the owner before posting.
